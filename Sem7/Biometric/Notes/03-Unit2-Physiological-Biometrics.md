## 1. Finger scan

Capturing a detailed map of the **friction ridges and valleys** on the fingertip. Not a flat
photograph — specialised sensors measure **physical, electrical or acoustic differences**, and
the system translates the pattern into a secure digital code.

### Sensor types

| Sensor | Principle | Where used |
|---|---|---|
| **Capacitive** | Thousands of microscopic capacitors store charge; ridges touch the surface while valleys leave tiny air gaps, and the variation in electrical contact maps the print. | Most common — laptop and phone power buttons |
| **Optical** | Shines light on the finger and takes a high-contrast digital picture of the ridge-and-valley layout. | Attendance systems, entry-level in-display readers |
| **Ultrasonic** | High-frequency sound waves pass through the outer skin layers and bounce back, producing a highly accurate **3D map**. | Premium smartphones. Very secure; **can scan through water, dirt or grease** |

### Pipeline

```
Image acquisition (hardware) → Image processing → Distinctive features → Template generation → Template matching
```

**Image acquisition.** The surface the finger is placed on is the **platen** (also loosely called
the scanner), made of glass, plastic, silicon or polymer. Depending on technology, contact
between fingerprint and platen is measured by chip-based cameras, ultrasonic imaging, or changes
in the capacitive field generated by the finger; measurements are converted to digital code. A
platen sits in a **finger-scan module** — platen plus a small printed circuit board plus a
standard connector — the basic building block of a peripheral or standalone device.

**Image processing.** The image must be converted to a usable format. Subroutines **eliminate
grey areas** by converting grey pixels to pure white or black according to their pitch
(binarisation). Ridges are then **thinned from roughly 5–8 pixels wide down to a single pixel**,
so features can be located precisely.

*Noise filtering / enhancement algorithms named in the deck:*

| Algorithm | Purpose |
|---|---|
| Median filter | Removes salt-and-pepper noise while preserving edges |
| Gaussian filter | Smooths Gaussian noise, reduces image variation |
| Wiener filter | Removes blur and noise adaptively |
| Bilateral filter | Reduces noise while preserving ridge edges |
| Histogram equalisation | Improves image contrast |
| CLAHE | Enhances local contrast without over-amplifying noise |
| **Gabor filter (most common)** | Enhances ridges using **local ridge orientation and frequency** |
| FFT-based enhancement | Enhances periodic ridge structure in the frequency domain |
| Anisotropic diffusion | Smooths homogeneous regions while preserving ridge boundaries |

*Ridge thinning* converts ridges into one-pixel-wide skeletons. Algorithms: **Zhang–Suen** (most
popular), **Guo–Hall**, morphological skeletonisation.

**Minutiae.** The distinctive features. Two principal types:
- **Ridge ending** — the point at which a ridge ends.
- **Bifurcation** — the point at which one ridge divides into two.

**Template creation.** Information mapped per minutia: **location, angle, type, quality, and
distance/position relative to the core**. Finger-scan images normally contain distortions and
**false minutiae** — from scars, sweat or dirt — that must be filtered out; a large percentage of
false minutiae are discarded so the stored template accurately reflects the biometric data. The
template is a **compact representation, not the full image**, storing ridge-ending coordinates
(x, y), bifurcation coordinates, orientation angle, ridge quality score and minutia type.
Minutiae-extraction algorithms named: **Crossing Number (CN)**, run-length encoding.

**Template matching algorithms:** minutiae matching, **Bozorth3 (NIST)**, graph matching, Hough
transform, Euclidean distance, cosine similarity (for deep-learning embeddings).

### Fingerprint system security — threats by pipeline stage

| Stage | Threat | Vulnerability | Impact |
|---|---|---|---|
| Sensor | Spoofing attack | Fake fingerprints from silicone, gelatin, latex or 3D prints | Unauthorised access |
| Sensor | Replay attack | Replaying previously captured fingerprint images | Bypass authentication |
| Preprocessing | Adversarial image attack | Maliciously modified fingerprint images | Incorrect feature extraction |
| Feature extraction | Feature manipulation | Altering minutiae points | False match or false reject |
| Communication channel | Man-in-the-middle | Intercepting fingerprint data | Data theft or modification |
| Template database | Template theft | Stealing stored templates | Identity theft |
| Template database | Template modification | Inserting or changing templates | Unauthorised enrolment |
| Matcher | **Hill-climbing attack** | Repeatedly modifying inputs until accepted | System compromise |
| Decision module | Decision override | Modifying authentication results | Unauthorised access |
| Entire system | Insider attack | Administrator misuse | Data leakage |

**Countermeasures for spoofing — the ones the deck names explicitly:** **liveness detection**,
multi-spectral fingerprint sensing, pulse detection, sweat-pore detection, temperature sensing.

**Countermeasures for the rest** (the deck sets this as an exercise — prepare these):

| Threat | Countermeasure |
|---|---|
| Replay attack | Nonces / timestamps / challenge–response, encrypted sensor-to-matcher channel, session freshness |
| Adversarial image attack | Adversarial training, input validation and sanity checks, quality gating |
| Feature manipulation | Digitally signed feature vectors, integrity checks between modules |
| Template theft | **Cancellable biometrics**, template encryption/hashing, secure element storage |
| Template modification | Strong access control, signed templates, audit logging, write-protection of the enrolment DB |
| Insider attack | Least privilege, separation of duties, mandatory logging and review, dual control on enrolment |

## 2. Automated Fingerprint Identification System (AFIS) **[textbook fill]**

An **AFIS** is a large-scale **1:N** fingerprint identification infrastructure, used by law
enforcement and civil ID programmes, as distinct from a single-user 1:1 verification device.

- **Inputs.** *Ten-print* cards (all ten fingers, rolled and slap impressions, captured under
  supervision) and **latent prints** lifted from crime scenes — partial, smudged, low quality.
- **Classification / binning.** Prints are first classified by global ridge pattern —
  **arch, tented arch, loop (left/right), whorl** — to reduce the search space before minutiae
  matching. This is why classification matters at scale: matching every probe against every
  record is infeasible.
- **Matching.** Minutiae-based matching produces a **candidate list** ranked by score, not a
  single yes/no answer.
- **Human adjudication.** A latent examiner makes the final identification decision from the
  candidate list. AFIS is therefore a **triage tool** whose useful FMR setting is deliberately
  loose (compare the casino card-counter case in Unit 1 §7).
- **Interoperability** depends on the data-interchange standards from Unit 1 §9 — ANSI/NIST-ITL
  and INCITS 378 minutiae format.

## 3. Face scan

Facial-scan technology uses distinctive features of the human face to verify or identify
individuals. It plays its main role in **1:N identification**: ID-card systems, booking stations,
and surveillance — and succeeds best where **cameras and imaging systems are already present**.

### Strengths

- Can **leverage existing image acquisition equipment**.
- Can search against **static images** such as driver's licence photographs.
- **The only biometric able to operate without user cooperation.**

### Weaknesses

- Changes in the **acquisition environment** reduce matching accuracy.
- Changes in **physiological characteristics** reduce matching accuracy.
- **Potential for privacy abuse**, precisely because enrolment and identification can be
  non-cooperative.

### Components

Ranges from software-only solutions processing existing **CCTV** feeds, up to full acquisition
and processing systems with cameras, workstations and back-end processors. In some systems the
core technology is optimised for specific cameras. Two basic engines, normally on the same PC or
device and working in close conjunction:

- **Face location engine** — finds and tracks faces in the field of view.
- **Face recognition engine** — compares those faces.

Template matching normally runs on a local or central PC, though the core technology has been
embedded in PDAs and mobile phones.

### Pipeline

```
Image acquisition → Image processing → Distinctive characteristic location → Template creation → Matching
```

**Image acquisition — 2D vs 3D.**
- **2D imaging:** standard RGB cameras, flat images; measurements extracted from pixel contrast
  and visible light.
- **3D and infrared:** an illuminator floods the face with invisible infrared light and a dot
  projector casts **over 30,000 infrared dots**; an IR camera reads them to build a **3D depth
  map**. Example: **Apple Face ID**.

Faces can be acquired from almost any static camera or video system of sufficient quality and
resolution. **High-quality enrolment is essential** — enrolment images define the characteristics
used in all future authentication. Distance from the camera reduces facial size and hence
resolution, though the technology can magnify smaller faces. **Lighting is the more severe
problem:** facial-scan generally cannot acquire over- or under-exposed images. Systems with
**automatic gain control**, able to adjust for lighting and skin tone, are more likely to yield
usable images. The deck notes that select Hispanic, Black and Asian individuals can be harder to
enrol and verify because acquisition devices are not always optimised for darker faces —
a **demographic bias in the sensor**, worth naming in any fairness question.

**Image processing — three operations.**
1. **Cropping** — the image is cropped so the ovoid facial region remains.
2. **Colour conversion** — colour images are normally converted to black and white to allow
   initial comparison on grayscale characteristics.
3. **Normalisation** — to overcome variations in orientation and distance. Related to the
   **face alignment** stage, which locates **face landmarks** (point markers of facial features).

**Distinctive characteristic location.** The face has distinguishable landmarks — the peaks and
valleys of the facial features — with about **80 nodal points**. Those measured include:
**distance between eyes, width of nose, depth of eye sockets, cheekbones, jaw line, chin.**
These are measured into a numerical code, a string of numbers representing the face — the
**faceprint** or **embedding**, e.g. a **128-dimensional floating-point array**.

**Detection and alignment.** *Detection:* **Haar cascades** or deep-learning **CNNs** scan the
image to isolate the face from the background using object texture and contrast. *Alignment:* the
image is normalised so eyes, nose and lips sit on a standard axis, giving consistent feature
extraction regardless of head tilt.

**Matching and verification.** Similarity is evaluated by the **distance** — **Euclidean** or
**cosine similarity** — between the captured face vector and the stored template vector. If the
distance falls below a predetermined similarity threshold, the identity is authenticated.

### Face recognition technique families

- **Feature-based methods** — properties and geometric relations such as areas, distances and
  angles between facial feature points, used as descriptors.
- **Appearance-based methods** — global properties of the face-image intensity pattern. These
  compute **basis vectors** to represent the face data efficiently, project faces onto those
  vectors, and use the **projection coefficients** as the representation. Algorithms:
  **PCA, LDA, ICA, LFA**, correlation filters, manifolds, tensorfaces.

See `01-PCA-Worked-Problems.md` for PCA in full, including both solved numericals.

### Liveness detection and modern security

To prevent spoofing with photos or masks, systems use **Presentation Attack Detection (PAD)**,
verifying liveness by tracking **micro-movements, eye blinks, or depth variation**.

Templates are further secured with **FIDO2 / WebAuthn** decentralised architecture, where data
stays locally encrypted in a **secure hardware enclave**. FIDO (Fast IDentity Online) is managed
by the **FIDO Alliance**, a non-profit industry consortium founded in **2012** by companies
including PayPal and Lenovo.

**FIDO architectural components**
- **Relying Party (RP)** — the application server that requests authentication and validates
  cryptographic signatures.
- **WebAuthn API** — standard JavaScript API in modern browsers and operating systems, letting
  the client application talk to the authenticator.
- **Authenticator** — generates and stores the key pair. *Internal:* Apple Secure Enclave,
  Android Keystore. *External / cross-platform:* YubiKey over USB or NFC.
- **CTAP2 (Client-to-Authenticator Protocol)** — lets an external hardware key or phone talk to
  the browser or OS client over USB or Bluetooth.

**Use case 1 — bank mobile app login (1:1, decentralised).**
1. Initial setup: user logs in with a biometric or traditional login.
2. Key creation: the app invokes the native OS API (Android **BiometricPrompt** or iOS
   **LocalAuthentication**); the device creates a FIDO2 key pair tied to that banking app.
3. Daily login: app requests a challenge from the bank server → phone prompts for a face scan →
   **the native hardware validates the face locally and never sends the biometric to the server**
   → on success the Secure Enclave releases the private key to sign the challenge → the signature
   is validated server-side and the user is logged in.

*Advantages:* **phishing-proof** — the key pair is bound to the specific app ID and domain, so a
fake phishing app cannot intercept or reuse the signature; **zero-trust biometrics** — the bank
server never holds, sees or processes facial data, only a cryptographic signature.

**Use case 2 — college attendance system.** Requires a **centralised 1:N** processing model,
which differs significantly from the localised 1:1 FIDO2 model. This is the exam contrast:
*decentralised 1:1 protects privacy; centralised 1:N is what identification actually needs.*

## 4. Iris scan **[textbook fill]**

- **What is measured:** the texture of the iris — the coloured annulus between pupil and sclera —
  containing furrows, ridges, crypts, rings, corona and freckles. The pattern is formed randomly
  during gestation, so even identical twins and a person's own left and right irises differ.
- **Acquisition:** near-infrared illumination, which reveals texture even in dark-brown irises
  and avoids pupil constriction from visible light.
- **Encoding:** the annulus is unwrapped into a polar strip and filtered (classically with 2D
  **Gabor** wavelets) into a compact binary **IrisCode**; matching is by **Hamming distance**.
- **Why it scores well:** very high **uniqueness** and **permanence** — the iris is stable through
  life and protected behind the cornea — giving extremely low FMR and low FNMR, which is why it is
  used for national-scale 1:N deduplication (Aadhaar, UAE border control).
- **Weaknesses:** requires user cooperation and reasonable positioning, higher device cost, and
  it is affected by glasses, contact lenses and certain eye conditions.

## 5. Retina scan **[textbook fill]**

- **What is measured:** the pattern of **blood vessels on the retina** at the back of the eye,
  captured with a low-intensity infrared light source while the user stares into an eyepiece at a
  fixed point.
- **Accuracy:** among the most accurate and hardest to spoof of all biometrics, since the trait is
  internal and requires a living eye.
- **Weaknesses:** the most **intrusive** modality and consequently the **least accepted** — close
  eye contact with the device, slow capture, poor tolerance of glasses; the pattern can also be
  altered by diabetes, glaucoma and retinal degeneration, which raises FNMR and creates a
  **health-inference privacy risk**.
- **Contrast for the exam:** *iris = external, coloured, camera at a distance, high acceptance;
  retina = internal, vascular, eyepiece contact, low acceptance.*

## 6. Ear scan **[textbook fill]**

- **What is measured:** the geometry and shape of the **outer ear (pinna)** — helix and antihelix
  curves, the concha, tragus and lobe — or the acoustic response of the ear canal.
- **Advantages:** the ear structure is stable in adulthood, is **not affected by expression**, and
  can be captured **passively** from a profile image, so it works alongside face in surveillance.
- **Weaknesses:** occlusion by hair, headwear and jewellery; smaller feature set than the face; a
  much smaller research and product base.

## 7. Palm print **[textbook fill]**

- **What is measured:** the friction-ridge surface of the whole palm — **principal lines** (heart,
  head, life lines), **wrinkles**, and the fine ridges and minutiae between them.
- **Advantage over fingerprint:** far larger surface area, so far more minutiae and more
  discriminative information; forensic value is high because roughly a third of latent prints
  recovered at crime scenes are palm rather than finger.
- **Acquisition:** flatbed-style or contactless scanners; low-resolution captures use the
  principal lines and texture, high-resolution (≥500 ppi) captures use minutiae like AFIS.

## 8. Hand vascular geometry analysis

Examining the patterns and structure of **blood vessels in the hand**, typically using **infrared
or near-infrared (NIR) imaging**. Applied in biometrics for identity verification, in medical
diagnostics for vascular disease, and in clinical monitoring of blood flow.

**1) Imaging techniques**
- **Infrared imaging** — IR light penetrates the skin and highlights subcutaneous vessels. This is
  the technique used in biometric systems.
- **Near-infrared spectroscopy (NIRS)** — more detailed analysis of blood oxygenation and
  haemoglobin levels.
- **Thermography** — thermal cameras detect heat emitted by the vessels, another way to visualise
  vascular patterns.

**2) Image processing and analysis**
- **Preprocessing** — enhance the captured images, remove noise, improve contrast to bring out the
  vascular structure.
- **Feature extraction** — width, length and **branching patterns** of the veins.
- **Pattern recognition** — machine-learning algorithms, e.g. **CNNs** trained to classify
  vascular patterns or detect anomalies indicating disease.

**3) 3D reconstruction (advanced)** — 3D models of the vascular network built from multiple 2D
images taken at different angles; useful in surgical planning and in-depth diagnostics.

**Challenges:** image quality dominates accuracy; **variability** from age, temperature and
physical activity must be handled by the algorithm; **ethical concerns** over storage and use of
vascular data; **regulatory approval** needed for medical use.

**Future directions:** integration with wearables for continuous vascular monitoring, AI-driven
diagnostics, personalised medicine tailored to an individual's circulatory system.

*Exam-worthy security point:* the vein pattern is **internal**, so unlike a fingerprint it leaves
no latent trace on surfaces and requires a live, warm hand — inherently strong against spoofing.

## 9. Knuckle biometric

The **finger-knuckle surface** is an emerging hand-based trait; its unique patterns have strong
potential for distinctive identification.

**Step 1 — noise removal.** Collected knuckle images carry different noise types from the capture
process (image shake and so on). Inconsistent pixel detail degrades the authentication system and
reduces overall security, so noise is removed with a **weighted median filter**: pixels are
checked against a **threshold** determined by analysing the pixel range of the image, and any
pixel deviating from it is replaced by the weighted median value. The weight is chosen by the
user; choosing the highest value smooths the image most effectively.

**Step 2 — knuckle-region extraction** using a **variational approach**, which selects the
optimal pixels during grouping, consumes minimum deviation and resolves the **non-convexity
problem**.

## 10. DNA biometrics

**DNA (deoxyribonucleic acid) provides the most reliable personal identification.** It is
**intrinsically digital**, and **does not change during a person's life or after death**.

DNA fingerprinting is used in criminal investigations, other forensic purposes, and paternity
testing. In these situations one aims to **match two DNA fingerprints** — for instance a sample
from a known person against one from an unknown person — using **DNA polymorphism analysis**.

*Contrast to note in an exam answer:* despite being the most reliable trait, DNA is not a
practical everyday authentication biometric — it is not real-time, requires a physical sample and
laboratory processing, is not currently automatable at the sensor, and carries the heaviest
privacy load of any trait because it discloses health and kinship.

## 11. Dental biometrics

Uses **dental radiographs** for human identification. Radiographs provide information about
teeth: **tooth contours, relative positions of neighbouring teeth, and shapes of dental work**
(crowns, fillings, bridges).

**Two main stages: feature extraction and matching.**

- **Feature extraction** — **anisotropic diffusion** to enhance the images, and a **Mixture of
  Gaussians** model to segment the dental work.
- **Matching**, in three sequential steps:
  1. **Tooth-level matching** — tooth contours matched by a **shape registration** method, dental
     work matched on overlapping areas; the distance between contours and the distance between
     dental work are combined using **posterior probabilities**.
  2. **Computation of image distances** — tooth correspondences are established between the query
     **post-mortem** radiograph and the database **ante-mortem** radiograph, and a distance based
     on the corresponding teeth measures similarity between the two radiographs.
  3. **Subject identification** — all distances between the post-mortem radiographs and the
     candidate ante-mortem radiographs are combined to establish the subject's identity.

*Application context:* forensic and mass-disaster victim identification, where soft tissue is
destroyed but teeth and dental work survive.

## 12. Cognitive biometrics — ECG and EEG

**Definition.** Cognitive biometrics are methods for authenticating a person based on the
measurement of **signals generated directly or indirectly from their thought processes**, which
reflect **mental and emotional states**. It acquires information through the collection of one or
more **biosignals**, using biological signals such as **EEG or ECG** as inputs to an
authentication system.

### EEG — electroencephalogram

- The EEG is a signal generated by the **collective activity of neurons**: brain activity produces
  an electrical signal recorded by placing **voltage-sensitive electrodes on the scalp surface**.
- A continuous signal is recorded from each electrode across the scalp, generating a **tremendous
  amount of data**.
- Electrode placement uses the **10–20 system**. Each electrode can be treated as a time series
  sampled at **0.5–1.0 kHz**, generating hundreds of megabytes of data that must then be analysed
  to extract useful information.
- **Recording system chain:** electrodes with conductive media → **amplifiers with filters**
  (amplifying microvolt signals into a range that can be digitised accurately) → **A/D converter**
  (analog to digital) → **recording device / computer** that stores and displays the data.

### ECG — electrocardiogram

A recording of the electrical activity of the heart. Three properties make it attractive as a
recognition trait:

1. **Liveness detection** — since the ECG records cardiac electrical activity, signals **can only
   be acquired from living individuals**.
2. **High security** — ECG signals are extremely difficult to counterfeit, and **no technology to
   artificially produce them has been developed**.
3. **Combined information** — analysis yields identity *plus* information on heart conditions and
   emotional and physical status.

*Flip side to mention for balance:* that same "combined information" is a **medical-privacy
risk** — the authentication signal doubles as a health record — and the signal varies with
exercise, stress and illness, which raises FNMR.
